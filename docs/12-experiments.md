# 实验记录、评估指标与可复现性

## 一个结果至少包含什么

| 类别 | 必须记录 |
|---|---|
| 软件 | repo commit、容器 image ID、Sim/Lab/Python/torch/RL 库版本 |
| 资产 | URDF/USD hash、配置层、依赖目录、joint/frame/单位约定 |
| 数据 | 来源、版本、split、模态、动作定义、归一化统计、许可 |
| 训练 | seed、环境数、物理/策略 dt、奖励、算法超参、父 checkpoint |
| 评估 | 固定策略文件、命令分布、episode 数、时长、成功/失败定义 |
| 产物 | log、配置快照、checkpoint、export、视频、机器可读 metrics |

同名文件可能被替换，路径不是版本。视频不保留完整状态，截图不保留运行配置；至少用 manifest 关联代码、资产与结果。

## 分层验收

```text
资源加载 → 物理/传感器 → 并行与重置 → 学习更新 → 断点/导出 → 闭环任务
```

任何一层 PASS 只证明该层：导出可加载不证明学到动作；reward 上升不证明任务泛化；机器人不跌倒不证明跟踪了指令。

| 任务 | 最小指标 | 额外检查 |
|---|---|---|
| FR5 部署 | joint/link/mesh 完整，有限步进 | 夹爪/工具/碰撞一致 |
| 接触抓取（待建设） | 保持抬升成功率、掉落率 | 穿透、滑移、力矩与接触 |
| 数据集 | 文件数、schema、数值、模态/时间对齐 | 分布、多样性、标签语义 |
| D1 轮足 | 速度/yaw MAE、跌倒率、episode 长度 | 滑移、关节/力矩饱和、停止漂移 |
| VLA 基准（待复现） | 各任务成功率、多 seed | 预处理/动作/控制器、训练评估泄漏 |
| 状态镜像 | 名称/单位、延迟、丢包/陈旧冻结 | 协议版本、夹爪不瞎补 |

## 评估 D1 的推荐矩阵

以下是建议验收方案，不是已达标记录。先用 8 组固定 `(vx m/s, yaw rad/s)`：`(0,0)`、`(0.2,0)`、`(0.4,0)`、`(-0.2,0)`、`(0,0.4)`、`(0,-0.4)`、`(0.3,0.3)`、`(0.3,-0.3)`；之后再扩展到训练边界与训练外条件。

### 现有评估器与完整验收的差距

| 当前 `run.py --mode evaluate` 实际提供 | 不能据此声称的能力 |
|---|---|
| 全时段、跨环境平均 vx/yaw 绝对误差与高度 | 没有逐环境最坏值、分位数或初始过渡剔除 |
| 总 episode reset 数 | 没有分离 terminated/超时，不是直接的跌倒率 |
| 初始观测批次原策略/导出策略动作比对 | 不代表全轨迹导出等价或闭环任务成功 |
| `--randomize` 可启用 startup 质量/摩擦与观测噪声 | 尚无延迟、外推力、地形或随机初始姿态的评估开关 |

evaluate 始终将 `reset_noise=False`，nominal 时换 seed 通常重复相同初态和动力学，不能把它当独立随机试验。随机化模式的 seed 影响已实现的 startup 参数/噪声，但仍不涵盖所有初态。环境自动 reset 后的状态也继续进入均值，必须同时报告失败，不能只看平均误差。

### 可执行起点与建议门槛

1. 分别训练 seed 42/43/44；每个候选 checkpoint 固定后，评估 seed 101/202/303。每条指令运行 64 环境、750 控制步＝15 s，从 reset 开始纳入落地过渡；每个 checkpoint、每个条件共 8×3×64＝1,536 个窗口。先 nominal，再 `--randomize`；nominal 重复 seed 不计作独立随机证据，各窗口也不假定统计独立。
2. 15 s 小于当前 20 s episode 上限，名义无重置窗口可先检查总 reset=0；发生重置时必须保留该失败窗口。若要得到每环境存活、首个跌倒和 ≥60 s 稳定性，先扩展采集器，分离 `terminated`/`truncated`，不能把正常超时算跌倒。
3. **项目候选阈值，非厂商标准**：每组指令 vx MAE≤0.10 m/s、yaw MAE≤0.15 rad/s；站立漂移速度≤0.05 m/s；15 s 内零异常重置。总体 JSON 只能初筛误差，逐环境达标、滑移、动作/力矩饱和和姿态峰值仍需新增轨迹记录，全部记录齐全后才可通过阶段验收。
4. 在完全相同的命令、场景随机参数、时长和计分窗口下比较 zero-action、固定轮速、随机策略及候选策略。固定轮速基线须锁定每条指令对应的四轮目标，不从最好片段事后挑选；现有 smoke 的全轮 2 rad/s 只适合前进机械检查，不能替代所有命令基线。完整基线评估入口待补。
5. 建议晋级规则：非站立指令等权宏平均 vx/yaw MAE 均不劣于两个确定性基线中该指标较优者，并在至少一项改善≥10%，异常重置不增加且满足上述绝对门槛。接近零误差的基线不计算相对改善，改报绝对差与置信区间；若无可分辨改善，不宣称策略优于基线。多训练 seed 分别报告，不只挑最好的一次。

现成单次 evaluate 命令不能完成这套协议；先增加逐环境/逐步记录与基线 runner，再按相同数据口径计分。延迟、外推力、地形条件目前也只是后续设计。

报告 MAE/RMSE、成功/跌倒比例、最坏值与分位数。剔除初始过渡时须明确窗口；不能只截最平稳的 3 秒。有限样本成功率给出样本数与置信区间，避免 1 次成功写成 100% 可靠。

若策略在相同速度下只是轮速开环，没有学到腿部协调，关节/接触轨迹中应能看出来；奖励上升不能替代这些证据。

## 日志的实用读法

TensorBoard 看分项 reward、episode length、termination、value loss、entropy、action std、learning rate；同时保存速度误差/动作/力矩轨迹。训练日志的平均 reward 可能跨不同长度 episode，比较时确认定义相同。

D1 现有日志 `Episode_Termination/fall` 是发生 reset 的子集中的比例，不是所有环境每步跌倒率。不要把它直接乘训练步数估算失败总量。

```bash
# 服务器宿主机：在 host 网络个人容器中启动仅本机可访问的 TensorBoard
docker exec isaacvnc_dengming /isaac-sim/python.sh -m tensorboard.main \
  --logdir /home/isaaclab_fairino/robotdog_d1_max/training/logs \
  --host 127.0.0.1 --port 6006
```

## 改动管理

一次实验主要改变一类因素：奖励、模型、随机化或网络。记录失败原因并保留失败日志，不能只保存最好视频。训练产物保留在服务器，公共文档仓库记录路径/指标，不提交大文件或 SDK/证书。

所有“历史验证”都应带日期和原始结果路径；如本次未重跑，直说。复验会写报告/日志时标注写入范围，不为了写手册长期占用 GPU。
