# 连接实验室 VPN：macOS 系统配置「1008」

本章针对用户确认的系统 VPN **1008**，不是 EasyConnect、OpenVPN Connect、ZeroTier 或 Tailscale。1008 是显示名称，不是端口号。
2026-11-19（Asia/Shanghai）只读核对了系统设置，未连接/断开 VPN，未更改地址、路由或凭据。

## 已核对的配置

| 项目 | 本机观察 | 使用时注意 |
|---|---|---|
| 入口 | 系统设置 → VPN → 1008 | 不要只看其他 VPN 的绿色状态 |
| 协议 | L2TP/IPSec | 使用 macOS 内置配置，不需要为它另装 OpenVPN 客户端 |
| 用户认证 | 密码 | VPN 账户/密码与服务器 SSH 账户/密码是不同用途 |
| 机器认证 | 共享密钥 | 与用户密码不同；重新配置时由管理员提供 |
| IPv4 | 使用 PPP | 先沿用原配置，不手填 192.168.190.208 |
| 发送所有流量 | 关闭 | 当前为分流配置；是否有目标路由仍需连接后检查 |
| 检查时状态 | 1008 已断开；Tailscale 已连接 | Tailscale 已连不等于已接入实验室 1008 VPN |

实际 VPN 服务器入口和账户已在本机界面核对，但不放入公共仓库。已有的 1008 可直接沿用保存的配置；换电脑向管理员领取入口、个人账户/密码和共享密钥。本机另有不进入仓库的连接说明，密码/共享密钥未读取或记录。

## 平时怎么连接

1. 确认 Wi-Fi/有线网络本身可用，打开 **系统设置 → VPN**。
2. 找到 **1008**，打开它对应的连接开关；不要误操作 Tailscale 的开关。
3. 如系统要求认证，由本人填写 VPN 凭据；不要把 SSH 密码当作 VPN 密码，或把用户密码当作共享密钥。
4. 等待 **1008 自己显示“已连接”**。只出现其他 VPN 的“已连接”不算。
5. 按下一节检查到服务器的 TCP 22，再执行 SSH。VPN 已连接也不能单独证明服务器可达。
6. 用完后可关闭 1008 的开关；这是断开连接，不需要删除配置。

以上为操作说明，**本次没有替用户打开连接开关，也没有完成连接成功验收**。

## 换 Mac 或重新建立配置

仅在原配置确实不存在时操作，不要先删掉能用的 1008。不同 macOS 版本菜单文字可能略有变化：

1. 在系统设置的 VPN 页面选择添加 VPN 配置，类型选 **L2TP over IPSec / L2TP/IPSec**。
2. 显示名称可填 `1008`，服务器地址填管理员给的 **VPN 网关**；它不是后面 SSH 使用的实验服务器地址。
3. 账户填管理员为本人分配的 VPN 用户名，用户认证选“密码”；机器认证选“共享密钥”，由本人填写相应凭据。
4. TCP/IP 先使用管理员要求的配置；本机现有配置为 **IPv4 使用 PPP**，并非手动固定 IP。
5. 本机“通过 VPN 连接发送所有流量”为关闭；重建时按管理员的分流/路由设计配置，不为碰运气直接开启全流量或覆盖默认路由。
6. 保存后连接，依次验证 VPN 状态、路由、TCP 22、SSH。不要关闭证书检查、防火墙或安全软件来代替排查。

已有配置的凭据由系统安全字段保存；不点击显示/导出，不复制到 README、Git、截图或诊断包。

## 连接后怎么确认

```bash
# macOS 本机；只读检查及有限网络探测，不修改配置
route -n get 192.168.190.200
nc -vz -G 3 192.168.190.200 22

# TCP 22 可达后再登录；密码在终端提示时自行输入，不写在命令里
ssh -o ConnectTimeout=8 dengming@192.168.190.200
```

| 结果 | 意义 | 下一步 |
|---|---|---|
| 1008 显示认证失败 | VPN 会话尚未建立 | 本人核对 VPN 账户、密码和共享密钥，必要时联系管理员 |
| 1008 已连接，但 TCP 22 超时 | 可能是路由、VPN ACL/客户端隔离、服务器或 SSH 服务问题 | 核对路由，再请可连接的同学检查服务器；不先改密码 |
| TCP 22 成功，SSH 拒绝密码 | 已到达某个 SSH 端点，但认证失败 | 核对目标主机、用户名/密钥；不改 VPN 网卡地址 |
| `Connection refused` | 到达目标或中间设备并收到拒绝 | 请管理员确认 SSH 监听/防火墙；不等于认证失败 |
| SSH 首次询问主机指纹 | 还需验证服务器身份 | 与管理员核对指纹；出现指纹变化也先核实，不直接删 known_hosts |

路由输出看 `interface`、目标前缀和 gateway。PPP 连接的接口通常叫 `pppN`，编号不固定；应以实际连接后的管理员网络设计为准，不能硬要求永远 `ppp0`。
如果访问仍沿普通 Wi-Fi 默认路由走，需核对是否真正连接了 1008、目标子网路由及其他 VPN 的影响；不要自行加静态路由或给 Wi-Fi 改同网段地址。

本次 1008 断开时，目标 `192.168.190.200` 匹配普通 `en0` 默认路由，TCP 22 超时。只能说明**当时未验证可达**，不能由此断言服务器关机、密码错误或另一条 VPN 有故障。
`scutil --nc list` 本次只列出 Tailscale，但系统设置界面确实有 1008；命令未列出时不能据此说配置不存在，应回到系统设置核对。

## 师兄的 Windows 怎么协助检查

Windows 的 VPN 配置须由管理员确认使用同一 L2TP/IPSec 服务；不能拿 Tailscale/OpenVPN 的“已连接”当作 1008 连接成功。本次没有检查 Windows 配置。

```powershell
# Windows 本机；只读检查，不更改网卡
Get-VpnConnection
Get-VpnConnection -AllUserConnection
ipconfig /all
route print
Test-NetConnection 192.168.190.200 -Port 22 -InformationLevel Detailed
```

两个 `Get-VpnConnection` 分别查看当前用户和全用户的系统 VPN；第三方客户端不一定在其中。不要把含入口/账户的原始输出公开提交。比较两台电脑的目标路由、VPN 虚拟地址、TCP 22 和 1008 会话状态，不复制对方的个人账户或 IP。

`192.168.190.208` 是此前讨论过的地址示例，**不是已批准分配给本机的静态地址**。本机现有配置使用 PPP，应先让 VPN 协商；若管理员要求静态分配，再确认地址唯一性、掩码、网关与路由，不能占用服务器的 `.200`。

## 实验室局域网与登录后的工作

人在实验室且已接入允许访问服务器的 LAN 时，可单独测试 `192.168.1.49:22`，再使用 `ssh dengming@192.168.1.49`。这是另一块网卡的地址，不保证在家能访问，也不代表连上任意 Wi-Fi 就可达。
登录后再按[环境与容器](01-infrastructure.md)进入 `isaacvnc_dengming`；VPN 本身不负责 Docker/Isaac 的启动。
更多网络分层检查见[排障](13-troubleshooting.md)；不要为诊断 VPN 重启他人容器或连接机器人控制器。
